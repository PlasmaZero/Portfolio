THE OVERVIEW

Blockchain

A collaborative treasury-wallet prototype with multi-owner approvals, timelocks, and spending caps.

What it explores

DAMD explores controlled payments from a shared treasury in an Ethereum test environment. The React interface exposes a proposal workflow, while Solidity contracts enforce approvals, delays, and spending limits.

The problem to solve

A shared wallet needs to communicate who can act, what approvals remain, and when a payment becomes executable. The interface must stay synchronized as accounts, networks, and contract state change.

Inside the build

01

Make approvals visible

Collaborated on a prototype supporting test ETH deposits, M-of-N owner approvals, payment timelocks, and per-payment and daily spending caps.

02

Connect interface and contract state

Integrated an ethers.js service for contract reads, transaction previews, signing requests, and refreshes after confirmations, account changes, and network switches.

03

Check the delivery path

Added GitHub Actions checks for linting, contract compilation, service and contract tests, and production builds.
